# دفتر — داشبورد مالی شخصی

[English](README.md)

دفتر حساب شخصی مخصوص کاربران فارسی‌زبان: ثبت درآمد، هزینه و بودجه ماهانه با تقویم شمسی، اعداد فارسی، راست‌چین و حالت تیره و روشن.

**نسخه‌ی زنده:** https://YOUR-APP.workers.dev
آدرس را باز کن و روی **«ورود به نسخه‌ی نمایشی»** بزن. ثبت‌نام لازم نیست.

**استک:** Next.js 14 (App Router) · TypeScript · Tailwind CSS · Recharts · FastAPI · SQLAlchemy 2 · JWT · SQLite / PostgreSQL

## دو حالت اجرا

| حالت             | چه چیزی لازم دارد                    | داده کجا می‌ماند                        | برای چه                 |
| ---------------- | ------------------------------------ | --------------------------------------- | ----------------------- |
| **نمایشی (دمو)** | فقط فرانت‌اند                        | مرورگر خود بازدیدکننده (`localStorage`) | نسخه‌ی زنده‌ی عمومی     |
| **کامل**         | فرانت‌اند + بک‌اند FastAPI + دیتابیس | SQLite یا PostgreSQL                    | استفاده‌ی واقعی و توسعه |

حالت نمایشی با `NEXT_PUBLIC_DEMO=1` روشن می‌شود. در این حالت فرانت به هیچ سروری درخواست نمی‌فرستد. یک API کوچک داخل مرورگر (`frontend/lib/demo.ts`) به همه‌ی درخواست‌های برنامه جواب می‌دهد، پس همه‌ی صفحه‌ها همان‌طور رفتار می‌کنند که با بک‌اند واقعی.

## قابلیت‌ها

- صفحه‌ی معرفی عمومی با پیش‌نمایش متحرک دفتر، امکانات، مراحل کار و پرسش‌های رایج
- صفحه‌های ورود و ثبت‌نام متحرک، با نمایشگر قدرت رمز عبور و نمایش/پنهان کردن رمز
- احراز هویت با JWT و ساخت دسته‌بندی‌های پیش‌فرض برای هر کاربر جدید (حالت کامل)
- ثبت، ویرایش و حذف تراکنش با فیلتر نوع، دسته و جستجو در توضیحات
- بودجه ماهانه برای هر دسته هزینه، با نوار پیشرفت و هشدار از ۸۰٪
- تراکنش تکرارشونده (اجاره، قسط و ...) که هر ماه در روز مشخص خودکار ثبت می‌شود
- نمودار سهم دسته‌ها، روند ۶ ماه اخیر و هزینه روزانه
- پشتیبانی کامل از تقویم شمسی (انتخاب تاریخ، گروه‌بندی ماهانه، سال کبیسه)
- خروجی CSV برای Excel و چاپ / PDF
- طراحی تک‌رنگ سیاه و سفید با تم تیره و روشن، راست‌چین، فونت وزیرمتن
- چیدمان ریسپانسیو، بررسی‌شده در عرض ۳۶۰ و ۷۶۸ پیکسل بدون اسکرول افقی

## نسخه‌ی نمایشی چه چیزی دارد

- یک حساب آماده با شش ماه درآمد و هزینه، بودجه‌ی چند دسته و سه مورد تکرارشونده، همه با تاریخ‌هایی نسبت به ماه شمسی امروز
- همه‌ی صفحه‌ها کاملاً قابل استفاده‌اند: افزودن، ویرایش و حذف تراکنش و دسته، تعیین بودجه، افزودن تراکنش تکرارشونده، فیلتر، جستجو و خروجی CSV
- در صفحه‌ی ورود و ثبت‌نام هر ایمیل و رمزی کار می‌کند، یا می‌شود از دکمه‌ی **«ورود با حساب آزمایشی»** استفاده کرد
- تغییرات فقط در مرورگر بازدیدکننده ذخیره می‌شوند و جایی ارسال نمی‌شوند. بازدیدکننده‌های دیگر آن‌ها را نمی‌بینند
- یک نوار بالای صفحه همین را توضیح می‌دهد و دکمه‌ی **«بازنشانی داده‌ها»** دارد
- در حالت نمایشی، تراکنش تکرارشونده‌ی جدید اگر روزش در این ماه گذشته باشد، همان لحظه تراکنش این ماه را هم می‌سازد. در بک‌اند واقعی تراکنش‌های تکرارشونده روی سرور ساخته می‌شوند

## راه‌اندازی

پیش‌نیاز: Node.js نسخه‌ی ۱۸ یا بالاتر برای فرانت‌اند و Python نسخه‌ی ۳٫۱۰ یا بالاتر برای بک‌اند (فقط حالت کامل).

### حالت نمایشی (فقط فرانت‌اند)

```bash
cd frontend
npm install
npm run build
npx serve@latest out
```

بیلد فایل‌های ثابت را در `frontend/out` خروجی می‌گیرد، پس در حالت نمایشی `npm run start` کار نمی‌کند. دستور `npx serve@latest out` آن‌ها را محلی سرو می‌کند (آدرس را چاپ می‌کند، معمولاً http://localhost:3000).

پرچم دمو از فایل `frontend/.env.production` خوانده می‌شود که محتوایش این است:

```
NEXT_PUBLIC_DEMO=1
```

`npm run dev` فایل `.env.production` را نمی‌خواند و در حالت کامل اجرا می‌شود. برای امتحان دمو در توسعه، فایل `frontend/.env.local` را با محتوای `NEXT_PUBLIC_DEMO=1` بساز و سرور توسعه را دوباره اجرا کن.

### حالت کامل (فرانت‌اند + بک‌اند)

بک‌اند:

```bash
cd backend
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --port 8000
```

محیط مجازی پیشنهاد می‌شود ولی اجباری نیست. در PowerShell ویندوز آن را با `.venv\Scripts\Activate.ps1` فعال کن.

مستندات API: http://localhost:8000/docs

بک‌اند فایل `.env` را خودکار نمی‌خواند. متغیرها را در شل تنظیم کن. در PowerShell:

```powershell
$env:SECRET_KEY = "a-long-random-string"
$env:DATABASE_URL = "sqlite:///./finance.db"
```

فرانت‌اند، در ترمینال دوم:

```bash
cd frontend
npm install
cp .env.local.example .env.local
npm run dev
```

آدرس برنامه: http://localhost:3000

اگر بعد از تغییر فایل‌ها ظاهر صفحه قدیمی ماند، کش را پاک کن و دوباره اجرا کن:

```powershell
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm run dev
```

### PostgreSQL

مقدار `DATABASE_URL` را مثل `postgresql://user:pass@host:5432/dbname` بگذار. پیشوند `postgres://` خودکار تبدیل می‌شود. جدول‌ها هنگام شروع ساخته می‌شوند.

### اختیاری: کاربر دمو در دیتابیس واقعی

`backend/seed_demo.py` کاربر `demo@example.com` را با داده‌ی نمونه در دیتابیسی که `DATABASE_URL` نشان می‌دهد می‌سازد. اجرای دوباره‌اش داده‌ی آن کاربر را به حالت اول برمی‌گرداند:

```bash
cd backend
python seed_demo.py
```

حساب را با متغیرهای `DEMO_EMAIL` و `DEMO_PASSWORD` و `DEMO_NAME` عوض کن. این فقط برای حالت کامل است و نسخه‌ی زنده‌ی عمومی از آن استفاده نمی‌کند.

## دیپلوی نسخه‌ی نمایشی روی Cloudflare

نسخه‌ی نمایشی بک‌اند و دیتابیس لازم ندارد. وقتی `NEXT_PUBLIC_DEMO=1` باشد، `next build` کل برنامه را به‌صورت فایل‌های ثابت در `frontend/out` خروجی می‌گیرد و Cloudflare Workers آن‌ها را به‌عنوان static assets سرو می‌کند (تنظیمش در `frontend/wrangler.jsonc` است).

دیپلوی مستقیم از GitHub با Workers Builds:

1. ریپو را روی GitHub بگذار.
2. در داشبورد Cloudflare به **Workers & Pages** برو، **Create application** و بعد **Import a repository** را بزن و ریپو را انتخاب کن.
3. این تنظیمات را بگذار:
    - نام پروژه / Worker: `finance-dashboard` (باید با `name` در `wrangler.jsonc` یکی باشد)
    - Root directory: `frontend`
    - Build command: `npm install && npm run build`
    - Deploy command: `npx wrangler deploy`
4. ذخیره و دیپلوی کن. برنامه روی `https://finance-dashboard.<your-subdomain>.workers.dev` بالا می‌آید. با هر push به شاخه‌ی اصلی دوباره دیپلوی می‌شود.

برای دیپلوی از کامپیوتر خودت، داخل `frontend` دستورهای `npm run build` و `npx wrangler deploy` را بزن.

آداپتر OpenNext استفاده نشده، چون نسخه‌ی نمایشی کاملاً ثابت است و آخرین نسخه‌های آداپتر Next.js جدیدتری از ۱۴ این پروژه می‌خواهند. بعد از دیپلوی، `YOUR-APP.workers.dev` را در بالای این فایل با آدرس واقعی عوض کن.

برای دیپلوی نسخه‌ی کامل، بک‌اند FastAPI را روی سرویسی که پایتون اجرا می‌کند (مثلاً Render) با یک دیتابیس PostgreSQL بالا بیاور، `NEXT_PUBLIC_DEMO` را حذف کن و قبل از بیلد `NEXT_PUBLIC_API_URL` را روی آدرس بک‌اند بگذار. بدون حالت نمایشی برنامه به‌صورت ثابت خروجی گرفته نمی‌شود و به هاستی نیاز دارد که Node را اجرا کند.

## متغیرهای محیطی

| متغیر                  | کجا       | توضیح                                                                            |
| ---------------------- | --------- | -------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_DEMO`     | فرانت‌اند | مقدار `1` حالت نمایشی را بدون بک‌اند روشن می‌کند. در `.env.production` تنظیم شده |
| `NEXT_PUBLIC_API_URL`  | فرانت‌اند | آدرس بک‌اند در حالت کامل، پیش‌فرض `http://localhost:8000`                        |
| `SECRET_KEY`           | بک‌اند    | کلید امضای JWT. در محیط واقعی مقدار تصادفی و بلند بگذار                          |
| `DATABASE_URL`         | بک‌اند    | پیش‌فرض یک فایل SQLite محلی                                                      |
| `FRONTEND_ORIGIN`      | بک‌اند    | آدرس(های) مجاز برای CORS، با ویرگول جدا شود                                      |
| `TOKEN_EXPIRE_MINUTES` | بک‌اند    | پیش‌فرض ۷ روز                                                                    |

متغیرهای `NEXT_PUBLIC_*` هنگام بیلد داخل فرانت قرار می‌گیرند و در مرورگر دیده می‌شوند، پس هرگز رمز یا کلید در آن‌ها نگذار. فایل‌های `.env` واقعی را از گیت دور نگه دار. `.gitignore` آن‌ها را رد می‌کند و فقط الگوهای `*.example` و `.env.production` را نگه می‌دارد.

## نکات طراحی

- مبلغ‌ها به‌صورت عدد صحیح (تومان) ذخیره می‌شوند تا جمع‌ها خطای اعشاری نداشته باشند.
- تبدیل تاریخ شمسی به‌طور مستقل در پایتون (`jalali.py`) و TypeScript (`lib/jalali.ts`) پیاده شده تا مرز ماه‌ها در هر دو سمت یکی باشد.
- `lib/api.ts` تنها جایی است که با شبکه کار دارد. در حالت نمایشی هر درخواست را به `lib/demo.ts` می‌فرستد که مسیرها، پیام‌های خطا و شکل پاسخ‌های بک‌اند را تقلید می‌کند.
- جهت صفحه‌ها با `dir="rtl"` روی ریشه‌ی هر صفحه مشخص شده. فیلد ایمیل و رمز عبور چپ‌به‌راست می‌مانند و اعداد علامت‌دار با کلاس `.num` ساخته می‌شوند تا مثبت و منفی جابه‌جا نشود.
- فضای اسکرول‌بار همیشه رزرو است (`overflow-y: scroll` روی `html`) تا هدر بین صفحه‌های کوتاه و بلند جابه‌جا نشود.
- انیمیشن‌ها به تنظیم `prefers-reduced-motion` احترام می‌گذارند.

## یادداشت‌ها

- داده‌ی نمایشی در `localStorage` مرورگر می‌ماند. پاک کردن اطلاعات سایت یا استفاده از پنجره‌ی خصوصی، دوباره از داده‌ی نمونه شروع می‌کند.
- حالت کامل تأیید ایمیل و بازیابی رمز ندارد. این یک پروژه‌ی نمونه‌کار است، نه محصول سخت‌شده.
